- **Clipboard threat model**: `docs/SECURITY-MODEL.md` §4.8 now lists the clipboard exploit paths and the safe ways to copy and paste. It corrects the earlier claim that `set-clipboard off` stops the container from writing the host clipboard: `tmux set-buffer -w` and `tmux refresh-client -l` bypass it, so the host terminal's clipboard permission is the real control. README tells iTerm2 users to keep that permission off and to copy with Option-drag.
